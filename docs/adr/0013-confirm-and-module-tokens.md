# ADR-0013. `confirm` перед необратимым действием и токены модулей

Статус: принято, 2026-11-10 (contract 0.3.0, требование R5 команды модулей).

**Контекст.** Результат устаревшей попытки ядро отбрасывает, но внешний эффект (пост в Instagram, списание) уже не отменить. Без проверки остаётся гонка «lease истёк → авто-retry → второй пост». Монотонный fence этого не решает: модуль узнаёт о нём только после действия.

**Решение.**
- `POST /api/v1/attempts/{id}/confirm {step_key, action, extend_seconds}` — единственный синхронный вызов модуля к ядру. В одной транзакции (`FOR UPDATE` попытки и шага, `FOR SHARE` run) ядро проверяет: модуль токена = модуль шага; попытка текущая и `running` с живым lease или `waiting`; run `running` или `waiting_human`; до дедлайна больше `extend_seconds`.
- Ответ всегда 200 с `result: ok | superseded | cancelled | deadline`; 401/403/404/422 — только для ошибок вызова.
- На `ok` lease продлевается до `now + extend_seconds` (1..600, по умолчанию 120), ставятся `confirmed_at` и `confirmed_until`, пишется `audit` (actor `module:<name>`, `action`).
- **Точка невозврата.** Подтверждённая попытка до `confirmed_until` не становится `lost`/`timed_out`; после — без результата уходит в `needs_attention` (`outcome_unknown`), никогда в авто-retry. Отмена run или шага даёт `needs_attention` (`cancelled_after_confirm`). Бюджетная отмена подтверждённые попытки не трогает. Повтор решает оператор через `retry step` с тем же `step_key` и `acknowledge_attention`; сверку делает модуль по своему ledger.
- **Токены модулей** (`module_tokens`): выдаются при apply модуля, показываются один раз, в БД только SHA-256; ротация с перекрытием (`expires_at`), отзыв (`revoked_at`). Docker-драйвер монтирует токен файлом секрета (`MF_SECRETS_DIR/<name>/…`) и не читает его, k8s кладёт в Secret. Admin-токен на `confirm` даёт 403, токен модуля принимается только на `confirm`.
- Модулю для этого нужны `MF_CORE_URL` и `MF_MODULE_TOKEN`; модулям без необратимых действий — нет.

**Альтернативы.** Монотонный fence в сообщениях (не закрывает гонку до действия); двухфазный протокол через брокер (асинхронный ответ, сложнее SDK); идемпотентность только на стороне модуля (не знает, что попытка уже заменена).

**Последствия.** Ядро должно быть доступно модулю по HTTP (gateway). Метрики `mf_attempt_confirms_total{result}`, `mf_outcome_unknown_total`. Приёмка: itest C5 «stale-результат и `confirm superseded`».
